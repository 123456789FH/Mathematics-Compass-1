# دليل تحويل بوصلة رياضيات ١ إلى منصة حية

## النتيجة بعد هذه الخطوات

سيتمكن كل عضو من إنشاء حسابه وحفظ نتائجه واحتياجاته، وسيشاهد المشرف لوحة جماعية محدثة. GitHub Pages يستضيف الواجهة، وSupabase يدير الحسابات وقاعدة البيانات والصلاحيات.

## ١. إنشاء مشروع Supabase

١. افتحي Supabase وأنشئي مشروعًا جديدًا.
٢. احفظي كلمة مرور قاعدة البيانات في مكان آمن.
٣. بعد اكتمال المشروع افتحي **SQL Editor**.

## ٢. إنشاء قاعدة البيانات

نفذي الملفات بالترتيب:

١. انسخي كامل محتوى `database/01_schema.sql` وشغليه.
٢. انسخي كامل محتوى `database/02_seed.sql` وشغليه.

الملف الأول ينشئ الجداول والدوال وسياسات الحماية. والملف الثاني يضيف المهارات و٢٦ سؤالًا ودورة المدرب خالد عزمي والمسارات الأولية.

## ٣. ربط الواجهة

من Supabase افتحي **Project Settings → API**، ثم انسخي:

- Project URL
- Publishable key أو anon public key

افتحي `js/config.js` وعدليه هكذا:

```js
window.BOUSLA_CONFIG = {
  SUPABASE_URL: "https://YOUR_PROJECT.supabase.co",
  SUPABASE_ANON_KEY: "YOUR_PUBLISHABLE_KEY",
  DEMO_MODE: false,
  APP_NAME: "بوصلة رياضيات ١"
};
```

المفتاح العام مصمم للاستخدام في المتصفح، وتبقى الحماية معتمدة على سياسات RLS. لا تستخدمي Service Role Key أبدًا داخل الموقع.

## ٤. إعداد عناوين المصادقة

داخل Supabase افتحي **Authentication → URL Configuration**.

ضعي رابط GitHub Pages النهائي في **Site URL**، مثل:

```text
https://USERNAME.github.io/REPOSITORY/
```

وأضيفي الرابط نفسه ضمن **Redirect URLs**. ويمكن إضافة رابط محلي للاختبار:

```text
http://localhost:8080/**
```

## ٥. نشر المشروع في GitHub

١. أنشئي مستودعًا جديدًا.
٢. ارفعي **محتويات مجلد المشروع** إلى جذر المستودع، وليس ملف ZIP.
٣. افتحي **Settings → Pages**.
٤. في Source اختاري **GitHub Actions**.
٥. سيعمل الملف `.github/workflows/pages.yml` تلقائيًا بعد كل رفع إلى الفرع `main`.

## ٦. إنشاء حساب المدير

١. افتحي رابط المنصة المنشور.
٢. أنشئي حسابك بالبريد.
٣. أكدي البريد إذا كان تأكيد البريد مفعّلًا.
٤. ارجعي إلى Supabase SQL Editor.
٥. افتحي `database/03_promote_admin.sql`، واستبدلي البريد ببريدك ثم شغليه.
٦. سجلي الخروج والدخول مرة أخرى؛ سيظهر قسم **نبض الملتقى** و**إدارة المحتوى**.

لإضافة مشرف آخر، استخدمي سطر الترقية إلى `supervisor` الموجود في الملف نفسه.

## ٧. اختبار التشغيل الحقيقي

أنشئي حسابين مختلفين:

- حساب عضو: أكملي تشخيصًا، حلي مسألة، وأرسلي احتياجًا.
- حساب مدير: افتحي نبض الملتقى، وتأكدي من ظهور المحاولة والطلب، ثم غيّري حالة الطلب.

اختبري أن العضو لا يستطيع رؤية أقسام المشرف حتى لو غيّر عنوان الصفحة؛ قاعدة البيانات نفسها تمنعه بسياسات RLS.

## ٨. إدارة المحتوى دون تعديل الملفات

من حساب المدير:

- **إدارة المحتوى → الأسئلة:** إضافة سؤال، خياراته، الإجابة، الشرح، الفخ والطريقة السريعة.
- **الدورات:** إضافة رابط موقع الدورة وقناة المدرب.
- **الإعلانات:** نشر لقاء أو تنبيه يظهر في الصفحة الرئيسية.
- **الأعضاء والصلاحيات:** ترقية عضو إلى مشرف أو مدير من حساب المدير.

## ٩. النسخ الاحتياطي والخصوصية

- لا تجمعي رقم الهوية أو بيانات حساسة لا تحتاجها المنصة.
- أخبري الأعضاء أن نتائجهم تُستخدم لإظهار مؤشرات جماعية للمشرفين.
- احتفظي بنسخة دورية من قاعدة البيانات من لوحة Supabase.
- لا تشاركي كلمة مرور قاعدة البيانات أو Service Role Key.
